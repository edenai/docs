To show the calls of one conversation together in Monitoring, Eden AI records a few facts about each LLM call next to its request log entry. None of them is prompt or answer text.

## What is recorded

| Fact | Where it comes from |
| --- | --- |
| Session id | The `session_id` body field, the `x-session-id` header, or the session a coding agent sends on its own (a header such as `x-claude-code-session-id`, Codex's `session-id` or `x-session-affinity`, or Claude Code's `metadata.user_id`) |
| Grouped session id | When a call names no session: the id of the session Eden AI groups it into, starting with `~`, stored with the request |
| End user id | `safety_identifier`, `user`, or Anthropic's `metadata.user_id`, as you send it |
| Agent ids | The subagent, turn and compaction markers a coding agent sends (Claude Code, Codex) |
| Trace ids | A W3C `traceparent` header you send |
| Step | How many messages the call carried, and whether it answered a user or tool results |
| Link hashes | Keyed hashes of the conversation's opening and of the last answer, so a call can be tied to the one it continues. They hold no text, and they are keyed with a secret only Eden AI holds, so they cannot be read back without it. |
| Tool names | The names of the tools a call used, **only when the request is saved** ([Log Retention](/v3/data-governance/data-retention)). Otherwise only how many there were. |

## What is not recorded

- Prompt or answer text, or tool arguments, unless you turned on Log Retention.
- Anything for calls that are not LLM calls, beyond the ids you send.

Under [zero data retention](/v3/data-governance/compliance-policies), requests are never saved, so tool names are never recorded: only their number, the ids and the hashes.

## Turn it off

An organization admin can turn it off in **Settings > Request Settings > Session details**. From then on these facts are not recorded for any call of the organization, and Monitoring lists no new sessions. The setting does not change routing, billing or [trace export](/v3/organization/trace-export), which sends the sessions you name but never one Eden AI grouped on its own.

## How long it is kept

These facts are stored with your request log entries and kept for as long as they are.

To group calls that name no session, Eden AI also keeps the link hashes of recent calls in its cache for 24 hours, then deletes them. A call that continues a conversation after that starts a new session.
