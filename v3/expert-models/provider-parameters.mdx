The `provider_params` field lets you pass provider-specific parameters that aren't part of Eden AI's unified schema. This gives you access to advanced or niche options offered by individual providers without breaking the standard request format.

## How It Works

Add a `provider_params` object to any Universal AI request. The contents are forwarded directly to the provider alongside the standard `input` fields.

```json
{
  "model": "{feature}/{subfeature}/{provider}[/{model}]",
  "input": {
    // Standard unified parameters
  },
  "provider_params": {
    // Provider-specific parameters passed through as-is
  }
}
```

## Basic Example

<CodeGroup>
```python Python
import requests

url = "https://api.edenai.run/v3/universal-ai"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

payload = {
    "model": "image/generation/openai/gpt-image-2",
    "input": {
        "text": "A futuristic city at sunset, cyberpunk style"
    },
    "provider_params": {
        "quality": "hd",
        "style": "vivid"
    }
}

response = requests.post(url, headers=headers, json=payload)
result = response.json()
print(result)
```

## Common Use Cases


### Image Generation: Style and Quality

Control output style and quality for image generation:

{/* skip-test: downloads the generated image from its result URL and opens it in a desktop viewer, neither of which a test run can do */}
<CodeGroup>
```python Python
import requests
import base64
from PIL import Image
from io import BytesIO

url = "https://api.edenai.run/v3/universal-ai"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

payload = {
    "model": "image/generation/openai/gpt-image-2",
    "input": {
        "num_images": 1,
        "text": "A watercolor painting of a mountain landscape",
        "resolution": "1792x1024"
    },
    "provider_params": {
        "style": "vivid",
        "quality": "hd" #Default is standard
    }
}
response = requests.post(url, headers=headers, json=payload)
data = response.json()

img_url = data["output"]["items"][0]["image_resource_url"]
img_response = requests.get(img_url)
img = Image.open(BytesIO(img_response.content))
img.save('image.png')
img.show()
```
</CodeGroup>

### Text to Speech: Voice Settings

Pass provider-specific voice parameters:

<CodeGroup>
```python Python
import requests

url = "https://api.edenai.run/v3/universal-ai"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

payload = {
    "model": "audio/tts/google/gemini-2.5-flash-tts",
    "input": {
      "voice": "achernar",
      "text": "Bonjour, j'adore la tourte.",
      "audio_format": "mp3"
    },
    "provider_params": {
      "language_code": "fr-FR",
      "prompt": "say this while crying"
    }
}

response = requests.post(url, headers=headers, json=payload)
print(response.json())
```
</CodeGroup>

## Parameter Validation and Allowlisting

For most subfeatures, Eden AI forwards `provider_params` directly to the provider without validation. Invalid parameters may cause provider errors.

However, certain subfeatures enforce an allowlist of accepted parameter paths:
- **Video generation:** `video/generation_async` validates parameters against supported provider options.
- **Web features:** Web search, scraping, crawling, and research tools enforce allowlists of accepted parameters.

When calling a gated subfeature, passing an unallowed parameter causes the request to be rejected with a `400 Bad Request` error.

### Discovering Allowed Parameters

To inspect which provider parameters are allowed for a subfeature, query the subfeature detail endpoint:

<CodeGroup>
```bash cURL
curl https://api.edenai.run/v3/info/video/generation_async \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```python Python
import requests

response = requests.get(
    "https://api.edenai.run/v3/info/video/generation_async",
    headers={"Authorization": "Bearer YOUR_API_KEY"}
)

params = response.json().get("provider_params")
print(params)
```
</CodeGroup>

The response includes a `provider_params` object mapping each provider to its accepted parameter paths:

```json
{
  "provider_params": {
    "kling": ["duration", "mode", "sound", "aspect_ratio"],
    "runway": ["duration", "ratio", "watermark"],
    "luma": ["aspect_ratio", "loop"]
  }
}
```

For subfeatures without restrictions, `provider_params` returns `null`.

You can also check the `documentation_url` field returned for each model in `GET /v3/info` to view the provider's official documentation.

## Important Notes

<Note>
- Gated subfeatures (such as video generation and web tools) enforce an allowlist of permitted `provider_params`. Unallowed parameters are rejected with HTTP 400.
- For unrestricted subfeatures, parameters pass through without validation.
- `provider_params` apply only to the specific provider specified in the `model` string. When switching providers, verify the parameters supported by the new provider.
</Note>
