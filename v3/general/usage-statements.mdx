A usage statement is one month of your organization's billed usage, split the way your finance team needs it: by [tag](/v3/general/tags), API key, member, feature or provider. It comes as a PDF summary and a CSV with every line.

A statement is not an invoice: it carries no VAT and there is nothing to pay. It shows what your usage was spent on.

## Opening your statements

In the [dashboard](https://app.edenai.run/), open **Monitoring → Statements**. The organization owner and members with the **Billing Management** [permission](/v3/organization/users-organisation#permissions) can open it.

The list shows the current month and every month with billed usage in the last twelve, starting with October 2026. Each month is in one of three states:

| State | Meaning |
|-------|---------|
| **In progress** | The month is still running, so its figures change. It is ready on the 1st of the next month at 12:00 UTC. |
| **Ready** | The month is over and not issued yet. |
| **Issued** | The statement has its number and never changes. |

A statement covers one UTC calendar month, in USD, for the whole organization, members who have left included. Calls made with [your own provider keys](/v3/general/byok) and [sandbox](/v3/general/sandbox) calls are not billed, so they are not in it.

## Choosing the split

Under **Split by**, choose one to three levels. Each level splits the one above it:

- a **tag key**, such as `client` or `project`: one row per value
- **API key**
- **Member**
- **Feature**
- **Provider**

For example, `client` then **API key** gives each client's spend, then each key within that client. Changes save automatically and apply to every month not issued yet.

Some rows are named for you:

- **Untagged (no client tag)**: calls sent without that tag key. Send the tag on each call, or give the API key [default tags](/v3/general/tags#as-default-tags-on-an-api-key).
- **Base key**: calls made with a member's account-level token, or from the Eden AI app.

Only the owner and people who can manage members can add the **Member** level. Once it is saved, everyone who can open statements sees it.

## PDF and CSV

| File | What it holds |
|------|---------------|
| **PDF** | The summary: the 20 largest values of each level, the rest in one **Other** row. Its rows add up to the total. |
| **CSV** | Every line, with the columns `Statement`, `Period start`, `Period end`, `Invoice`, one column per level, `Calls` and `Cost (USD)`. Its cents add up to the total. |

Use **Preview PDF** to see the PDF before downloading. A split of more than 50,000 lines is refused: choose fewer levels.

## Issuing a month

A **Ready** month is issued by its first download (**Issue and download**) or by the monthly email, with the split saved at that moment. Issuing gives it a number such as `ST-2026-10-0001`, counted per organization, and freezes it: every later download returns the same document.

To read an issued month split another way, choose **Current split**. Its downloads are re-split copies, marked as such and built from current data, so usage that arrived after the month was issued shows up in them. The issued statement stays as filed; choose **As issued** to get it again.

Until a month is issued, **Download draft** gives a CSV marked as a draft, which issues nothing.

## Monthly email

Turn on **Email each month** to issue last month's statement on the 1st after 12:00 UTC and email its PDF and CSV to the owner, the billing managers and the billing contacts. Billing contacts are set in **Settings → Billing → Billing contacts**.

## With postpaid billing

On a postpaid plan, a month's statement adds up to the usage line of that month's [invoice](/v3/general/invoices) and names the invoice. When the two differ, the PDF and the page show the difference.

The monthly email waits until that invoice is sent. Each whole-month invoice also links to its statement in the invoice memo.

## Accessing statements via API

You can list statement months, retrieve monthly breakdowns, and download statement PDF and CSV files programmatically using a [management key](/v3/organization/management-api) with the `manage:read` scope.

### List statement months

`GET /v3/manage/billing/statements/` returns the last twelve months with billed usage, newest first, alongside your current split configuration and email preference.

<CodeGroup>

{/* skip-test: GET /v3/manage/billing/statements/ requires a management key with manage:read scope */}
```bash cURL
curl "https://api.edenai.run/v3/manage/billing/statements/" \
  -H "Authorization: Bearer $MANAGEMENT_KEY"
```

{/* skip-test: GET /v3/manage/billing/statements/ requires a management key with manage:read scope */}
```python Python
import requests

response = requests.get(
    "https://api.edenai.run/v3/manage/billing/statements/",
    headers={"Authorization": "Bearer YOUR_MANAGEMENT_KEY"},
    timeout=30,
)
response.raise_for_status()

overview = response.json()
print(f"Configured split: {overview['levels']}")
for month in overview["months"]:
    spend = month["total_cents"] / 100
    print(f"{month['period']}: {month['status']} ({spend:.2f} USD)")
```

</CodeGroup>

```json Response
{
  "levels": ["tag:client", "api_key"],
  "email_monthly": true,
  "months": [
    {
      "period": "2026-10",
      "status": "issued",
      "total_cents": 35000,
      "calls": 1250,
      "number": "ST-2026-10-0001",
      "invoice_number": "INV-2026-10-001",
      "invoice_usage_cents": 35000,
      "issued_at": "2026-11-01T12:05:00Z"
    }
  ]
}
```

Each month has one of three statuses:

- `preliminary`: The month is still running (until the 1st of the following month at 12:00 UTC).
- `available`: The month has ended and is ready to be issued.
- `issued`: The statement has been finalized with a permanent number and frozen split.

### Retrieve statement breakdown

`GET /v3/manage/billing/statements/{period}/`, where `{period}` is formatted as `YYYY-MM` (such as `2026-10`), returns that month's detailed breakdown folded level by level.

If the period is malformed, the endpoint returns `404`. A month that has not started yet returns `400`, and a month that is not ready yet returns `409`.

<CodeGroup>

{/* skip-test: GET /v3/manage/billing/statements/{period}/ requires a management key with manage:read scope */}
```bash cURL
curl "https://api.edenai.run/v3/manage/billing/statements/2026-10/" \
  -H "Authorization: Bearer $MANAGEMENT_KEY"
```

{/* skip-test: GET /v3/manage/billing/statements/{period}/ requires a management key with manage:read scope */}
```python Python
import requests

period = "2026-10"

response = requests.get(
    f"https://api.edenai.run/v3/manage/billing/statements/{period}/",
    headers={"Authorization": "Bearer YOUR_MANAGEMENT_KEY"},
    timeout=30,
)
response.raise_for_status()

statement = response.json()
print(f"Statement {statement['number']}: {statement['total_cents'] / 100:.2f} USD")
```

</CodeGroup>

### Download PDF and CSV files

`GET /v3/manage/billing/statements/{period}/pdf/` and `GET /v3/manage/billing/statements/{period}/csv/` return the statement file as a binary download.

<Warning>
Downloading via the API returns the issued statement if the month has already been issued, or a draft file otherwise. Unlike dashboard downloads, API downloads never issue a month: they leave unissued months in their draft state so your configured split is not frozen prematurely.
</Warning>

### Service availability

Usage statements read aggregated data from ClickHouse. If ClickHouse is temporarily unavailable, statement endpoints return `503` with a message asking you to retry shortly.
