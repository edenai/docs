Eden AI's provider plugin adds Eden AI to Hermes Agent as the `edenai` provider: one install command and one API key.

## Overview

[Hermes Agent](https://hermes-agent.nousresearch.com) is an open-source, self-hosted AI agent from Nous Research. It runs as a persistent background process with its own memory and skills, and reaches you from the CLI and through messaging platforms. Pointed at Eden AI, it can use the function-calling chat models in the [Eden AI catalog](/v3/llms/listing-models) with a single Eden AI key.

The [Eden AI plugin](https://github.com/edenai/hermes-edenai-provider) gives Hermes:

- **The model list**: Hermes' picker reads Eden AI's catalog, one entry per model, with each model's context window.
- **Sessions**: each conversation sends a session id that survives context compression, so it stays on one provider and its prompt cache, and [Monitoring](/v3/data-governance/session-details) and [Trace Export](/v3/organization/trace-export) show it as one session. A subagent started with `delegate_task` appears as a thread of its parent's session, and the calls are labelled Hermes Agent.
- **Reasoning effort**: Hermes' reasoning setting is sent as `reasoning_effort`.

<Note>
Hermes is an **agent**, so every request it sends includes a `tools` (function-calling) parameter. Point it at a model that supports function calling. See [Model naming](#model-naming).
</Note>

## Prerequisites

- Hermes Agent already installed. If not, run the one-line installer:

<CodeGroup>
```bash macOS / Linux / WSL2
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

```powershell Windows
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```
</CodeGroup>

- Eden AI API key from [app.edenai.run](https://app.edenai.run) → **API Keys**

## Setup

### 1. Install the Eden AI plugin

<CodeGroup>
```bash Terminal
hermes plugins install edenai/hermes-edenai-provider/model-providers/edenai --enable
```
</CodeGroup>

### 2. Add your API key

The installer asks for the key. To keep it, add it to Hermes' secrets file (`hermes config env-path` prints its location) as **`EDENAI_API_KEY`**:

<CodeGroup>
```bash .env
EDENAI_API_KEY=YOUR_API_KEY
```
</CodeGroup>

<Note>
- Keep the key in the `.env` file, not in `config.yaml`. Any environment variable named `EDENAI_API_KEY` works too.
- Eden AI bills the calls to the key you used. See [monitoring](/v3/general/monitoring) to track consumption and cost.
</Note>

### 3. Start Hermes

<CodeGroup>
```bash Terminal
hermes chat --provider edenai -m '~claude-sonnet-latest'
```
</CodeGroup>

Or run `hermes model` and pick **Eden AI** to make it the default. For a one-shot, non-interactive run (handy for scripts or a quick smoke test):

<CodeGroup>
```bash Terminal
hermes chat --provider edenai -m '~claude-sonnet-latest' -Q -q "Reply with exactly one word: pong"
```
</CodeGroup>

### EU endpoint

Set `EDENAI_BASE_URL` in the same `.env` file to route Hermes through Eden AI's EU endpoint:

<CodeGroup>
```bash .env
EDENAI_BASE_URL=https://api.eu.edenai.run/v3
```
</CodeGroup>

## Model naming

Hermes needs **function calling**, so its picker lists only the models that support it. Names starting with `~` follow the newest model of a family, so the config does not go stale:

- `~claude-sonnet-latest`: balanced reasoning and reliable tool calling, a good default
- `~claude-haiku-latest`: fast and cheap
- `~gpt-mini-latest`: OpenAI's small model
- `~gemini-pro-latest`: Google's flagship

[Provider routing](/v3/llms/provider-routing) picks the provider for each call. To pin a provider, use its `provider/model` id, such as `anthropic/claude-sonnet-latest`. The full list, with each model's capabilities, is in [List LLM Models](/v3/llms/listing-models).

## Switching models

Set the default with `hermes config set model.default <model>`, or override it for one session:

```bash
hermes chat --provider edenai -m '~gemini-pro-latest'
```

### Fallbacks

A backup model can come from either side, and the two are separate mechanisms.

**Hermes switches models.** Hermes tries the entries of its `fallback_providers` list in order when the primary fails with a rate limit, an overload or a connection error. `hermes fallback add` opens the same picker as `hermes model` and needs a terminal. You can also edit `config.yaml`:

```yaml
fallback_providers:
  - provider: edenai
    model: ~gemini-pro-latest
```

**Eden AI switches models.** A [routing policy](/v3/llms/routing-policies) is a saved model chain that Eden AI runs for you. Create one whose targets all support function calling, then make its name Hermes' model:

```bash
hermes config set model.default policy/<name>
```

Eden AI runs the policy's chain for `policy/<name>`; a request that names an ordinary model runs that model.

## Without the plugin

<Accordion title="Use Hermes' custom provider instead">

Hermes' `custom` provider accepts any OpenAI-compatible endpoint. Configure it with the Eden AI base URL and a function-calling model:

```bash
hermes config set model.provider custom
hermes config set model.base_url https://api.edenai.run/v3
hermes config set model.default '~claude-sonnet-latest'
```

This writes to Hermes' config file (`hermes config path` prints its location: `~/.hermes/config.yaml` on macOS and Linux, `%LOCALAPPDATA%\hermes\config.yaml` on Windows, or `$HERMES_HOME/config.yaml` when you set `HERMES_HOME`). The result looks like:

<CodeGroup>
```yaml config.yaml
model:
  provider: custom
  base_url: https://api.edenai.run/v3
  default: ~claude-sonnet-latest
```
</CodeGroup>

Hermes derives the key's environment-variable name from the base URL host, so `api.edenai.run` maps to `EDENAI_API_KEY` in the same `.env` file. `base_url` must be `https://api.edenai.run/v3`, without a trailing `/chat/completions`: the OpenAI-compatible client appends that for you.

Without the plugin, Hermes sends no session id, so Eden AI groups a conversation's calls on its own, as an inferred session. With the plugin installed, a `custom` endpoint at an `edenai.run` host uses the plugin's profile too.

</Accordion>

## Expert Models as Tools (MCP)

Eden AI also hosts an [MCP server](/v3/expert-models/mcp-server) that exposes the expert model catalog (OCR, web search, speech, translation and more) as tools. Add it under `mcp_servers` in Hermes' config file (`hermes config path` prints the location):

```yaml
mcp_servers:
  edenai:
    url: https://mcp.edenai.run/mcp
    headers:
      Authorization: Bearer ${EDENAI_API_KEY}
```

Hermes expands `${VAR}` in server entries, and loads the `.env` file that `hermes config env-path` prints into its environment at startup, so this reuses the `EDENAI_API_KEY` you already added in [step 2](#2-add-your-api-key). The server's tools register into Hermes' normal tool registry at startup, so they chain with built-in tools in a single workflow. Run `/reload-mcp` in an active chat to pick up config changes without a restart.

See the [MCP server page](/v3/expert-models/mcp-server) for the full tool catalog and the conventions its tools share.

## Troubleshooting

### Eden AI is missing from `hermes model`

Run `hermes plugins list` to check that `edenai` is installed and enabled, and that `EDENAI_API_KEY` is set in the `.env` file `hermes config env-path` prints.

### `401` / `Invalid API key` or `Invalid token`

Eden AI does not recognize the key: it answers `Invalid API key` for a wrong or revoked `sk-eden-...` key and `Invalid token` for a token of any other shape. Create a fresh one at [app.edenai.run](https://app.edenai.run) → **API Keys**. Confirm `EDENAI_API_KEY` is set in Hermes' `.env` (`hermes config env-path`) and has no leading or trailing spaces.

### `Model(s) not found or inactive`

Eden AI returns this `400` when the model id is not in the catalog. Use a name the catalog lists, for example `~claude-sonnet-latest`, or a `provider/model` id such as `anthropic/claude-sonnet-latest`.

### Connection issues

With the `custom` provider, confirm `base_url` is exactly `https://api.edenai.run/v3`. Check Eden AI status at [app-edenai.instatus.com](https://app-edenai.instatus.com).
