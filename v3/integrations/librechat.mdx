LibreChat reads Eden AI from a custom endpoint in `librechat.yaml`, and the stock Docker setup does not mount that file, so this page sets the key, writes the endpoint, and then adds the mount.

## Overview

[LibreChat](https://librechat.ai) is a free, open-source AI chat platform. A custom endpoint speaks the OpenAI chat completions format, which Eden AI serves at `https://api.edenai.run/v3`. Every model you list appears in LibreChat's model picker under the endpoint name, so one key reaches OpenAI, Anthropic, Google and the rest of the 500+ models.

## Prerequisites

- Docker and Docker Compose
- An Eden AI API key from [app.edenai.run](https://app.edenai.run) → **API Keys**

## Setup

### 1. Clone LibreChat and set the key

<CodeGroup>
```bash Terminal
git clone https://github.com/danny-avila/LibreChat.git
cd LibreChat
cp .env.example .env
echo 'EDEN_AI_API_KEY=YOUR_API_KEY' >> .env
```
</CodeGroup>

Replace `YOUR_API_KEY` with your Eden AI key.

The container loads `.env`, so `librechat.yaml` can refer to the key as `${EDEN_AI_API_KEY}` and the key stays out of the YAML file.

### 2. Create librechat.yaml

<CodeGroup>
```yaml librechat.yaml
version: 1.3.17
cache: true

endpoints:
  custom:
    - name: "Eden AI"
      apiKey: "${EDEN_AI_API_KEY}"
      baseURL: "https://api.edenai.run/v3"
      models:
        default:
          - "anthropic/claude-sonnet-latest"
          - "openai/gpt-latest"
          - "vertex/gemini-pro-latest"
          - "openai/gpt-mini-latest"
        fetch: false
      titleConvo: true
      titleModel: "openai/gpt-mini-latest"
      modelDisplayLabel: "Eden AI"
```
</CodeGroup>

### 3. Mount the file into the container

LibreChat's own `docker-compose.yml` binds `.env` and its data folders, but not `librechat.yaml`. Without a mount, LibreChat starts without reading the file and "Eden AI" never appears. Add the mount in a `docker-compose.override.yml` next to the stock file:

<CodeGroup>
```yaml docker-compose.override.yml
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```
</CodeGroup>

### 4. Start LibreChat

<CodeGroup>
```bash Terminal
docker compose up -d
```
</CodeGroup>

Open `http://localhost:3080`, create an account, and select **Eden AI** in the endpoint menu.

For a manual install, the other config options, and authentication, see the [LibreChat documentation](https://www.librechat.ai/docs).

## Model naming

Eden AI model ids are `provider/model`, for example `anthropic/claude-sonnet-latest`, `openai/gpt-latest` and `vertex/gemini-pro-latest`. The `-latest` aliases always resolve to the current model of that line. Browse the full list in [List LLM Models](/v3/llms/listing-models).

With `fetch: false`, LibreChat shows only the ids in `models.default`. Set `fetch: true` to have LibreChat read every chat model from `https://api.edenai.run/v3/models`, which returns over a thousand entries, so keep the explicit list unless you want the full catalog in the picker.

## Troubleshooting

### Eden AI does not appear in LibreChat

1. Check that the override file is in place and that `docker compose config` lists `/app/librechat.yaml` under the `api` volumes.
2. Run `docker compose logs api` and look for a `librechat.yaml` validation error. Check that the file is valid YAML.
3. Restart after any change to `librechat.yaml` or `.env`:
   ```bash
   docker compose down
   docker compose up -d
   ```

### 401 errors

1. Check that `.env` contains `EDEN_AI_API_KEY` with no extra spaces and that `librechat.yaml` refers to it as `${EDEN_AI_API_KEY}`.
2. Check that `baseURL` in `librechat.yaml` is `https://api.edenai.run/v3`.
3. Test the key outside LibreChat:
   ```bash
   curl -X POST https://api.edenai.run/v3/chat/completions \
     -H "Authorization: Bearer YOUR_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "model": "anthropic/claude-sonnet-latest",
       "messages": [{"role": "user", "content": "test"}]
     }'
   ```
4. Restart services after changing `.env`.
