OpenConnector exposes Eden AI as two actions: a model list and a non-streaming chat completion. This page runs the gateway with Docker, stores your Eden AI key as a connection and calls the `edenai` service.

## Overview

[OpenConnector](https://github.com/oomol-lab/open-connector) is an open-source, self-hosted auth gateway that connects SaaS providers to AI agents through SDK, CLI, MCP, HTTP and OpenAPI. Eden AI is one of its **built-in connectors**, so an agent wired through OpenConnector can call models from OpenAI, Anthropic, Google, Mistral and more behind one key, with the Eden AI billed cost when Eden AI returns one.

The connector exposes chat completions (non-streaming only) and a model list. For EU data residency, see [EU Data Residency Endpoint](/v3/data-governance/eu-endpoint): the connector's base URL is fixed to `https://api.edenai.run/v3` and cannot be pointed at the EU endpoint.

## Prerequisites

- Docker with Compose, and Git
- An Eden AI API key from [app.edenai.run](https://app.edenai.run)

## Setup

### 1. Start OpenConnector

Clone the repository and start the published image:

```bash
git clone https://github.com/oomol-lab/open-connector
cd open-connector
docker compose up
```

This pulls `ghcr.io/oomol-lab/open-connector:latest` and serves the console at `http://localhost:3000` and the API reference at `http://localhost:3000/docs`. For anything beyond a trial, pin a released version (for example `v1.9.4`) instead of `latest`.

### 2. Store your Eden AI key

<CodeGroup>
```bash Add credential
curl -s -X PUT http://localhost:3000/api/connections/edenai \
  -H 'content-type: application/json' \
  -d '{"authType":"api_key","values":{"apiKey":"YOUR_API_KEY"}}'
```
</CodeGroup>

OpenConnector checks the key with a request to Eden AI's `/models`, so a bad key is rejected at this step. If you set `OOMOL_CONNECT_ADMIN_TOKEN`, send it as `authorization: Bearer <token>` on `/api` calls.

The connector reads no Eden AI environment variable. The key is stored as the `edenai` connection (`authType: api_key`, field `apiKey`) and sent to Eden AI as a bearer token. Run the same `PUT` with a new key to replace it. Set `OOMOL_CONNECT_ENCRYPTION_KEY` to encrypt stored credentials at rest.

### 3. Call Eden AI

<CodeGroup>
```bash Call Eden AI
curl -s -X POST http://localhost:3000/v1/actions/edenai.create_chat_completion \
  -H 'content-type: application/json' \
  -d '{
    "input": {
      "model": "openai/gpt-latest",
      "messages": [{"role": "user", "content": "Hello! How are you?"}]
    }
  }'
```
</CodeGroup>

If you created a runtime token, send it as a bearer token on `/v1` calls. The response includes the standard OpenAI-compatible fields plus a top-level `cost` field with the Eden AI billed cost, when Eden AI returns one. `stream: true` is rejected.

## Model naming

The `edenai` service exposes two actions: `edenai.list_models` and `edenai.create_chat_completion`. Use the `provider/model` format, for example `openai/gpt-latest`, `anthropic/claude-sonnet-latest` or `mistral/mistral-large-latest`. Call `edenai.list_models` or see [List LLM Models](/v3/llms/listing-models) for the catalog.

## Troubleshooting

### `401` from `/api` or `/v1`

An admin token or runtime token is configured. Send it as a bearer token.

### The key is rejected when you store it

OpenConnector validates the key against Eden AI's `/models`. Eden AI answers 401 with `Invalid API key` for a wrong or revoked `sk-eden-` key and `Invalid token` for other token shapes. Create a regular API key at [app.edenai.run](https://app.edenai.run/settings/api-keys).

### Streaming fails

The connector accepts only `stream: false` or no `stream` field.
