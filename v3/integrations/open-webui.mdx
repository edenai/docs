Pointing Open WebUI's OpenAI connection at Eden AI moves chat only: every other feature reads its own base URL and key, and this guide sets each one.

## Overview

[Open WebUI](https://github.com/open-webui/open-webui) is a self-hosted web interface for AI models. Its OpenAI connection accepts any OpenAI-compatible base URL, so pointing it at `https://api.edenai.run/v3` lists Eden AI's chat models in the model picker and sends chats through Eden AI.

Open WebUI sends embeddings, speech-to-text, image generation and web search through settings of their own. Each one reads its own base URL and key, so the chat connection alone does not move them to Eden AI. The sections below set each one.

## Prerequisites

- Docker
- An Eden AI API key from [app.edenai.run](https://app.edenai.run) → **API Keys**

## Setup

<Note>
Open WebUI reads the environment variables on this page only on its first start and saves them in its database. From then on the saved values win, so on an existing install change them in the Admin Panel instead, or set `ENABLE_PERSISTENT_CONFIG=false` to make Open WebUI read the environment on every start. This applies to every block below.
</Note>

### New install

<CodeGroup>
```bash bash
docker run -d \
  --name open-webui \
  -p 3000:8080 \
  -v open-webui:/app/backend/data \
  -e OPENAI_API_BASE_URL=https://api.edenai.run/v3 \
  -e OPENAI_API_KEY=YOUR_API_KEY \
  ghcr.io/open-webui/open-webui:main
```
</CodeGroup>

Add the variables from the sections below to this command before the first start, as more `-e` flags or with `--env-file .env`.

Open `http://localhost:3000` and register the first user, who becomes the admin. For Docker Compose, authentication, HTTPS and the other deployment options, see the [Open WebUI documentation](https://docs.openwebui.com).

### Existing install

1. Open the **Admin Panel**, then **Settings**, then **Connections**.
2. Under **OpenAI API**, select **Add Connection**.
3. Set the URL to `https://api.edenai.run/v3` and enter your Eden AI API key.

## Model naming

Open WebUI lists the models from `GET https://api.edenai.run/v3/models`, so there is nothing to add by hand. Eden AI model ids are `provider/model`, for example `anthropic/claude-sonnet-latest`, `openai/gpt-latest` and `vertex/gemini-flash-latest`. The `-latest` aliases always resolve to the current model of that line. To hide or rename models, use **Admin Panel**, **Settings**, **Models**. Browse the full list in [List LLM Models](/v3/llms/listing-models).

To run Open WebUI's background tasks (chat titles, tags) on a cheaper model, set a task model:

<CodeGroup>
```bash .env
TASK_MODEL_EXTERNAL=openai/gpt-mini-latest
```
</CodeGroup>

## Embeddings for RAG

By default Open WebUI embeds documents locally. To embed them through Eden AI, select the OpenAI engine and give it its own base URL and key:

<CodeGroup>
```bash .env
RAG_EMBEDDING_ENGINE=openai
RAG_EMBEDDING_MODEL=openai/text-embedding-3-small
RAG_OPENAI_API_BASE_URL=https://api.edenai.run/v3
RAG_OPENAI_API_KEY=YOUR_API_KEY
```
</CodeGroup>

On an existing install, open **Admin Panel**, **Settings**, **Documents**, set **Embedding Model Engine** to `OpenAI`, and fill in **API Base URL**, **API Key** and **Embedding Model**. Reindex your knowledge bases after you change the embedding model. List the embedding models available to you with `GET https://api.edenai.run/v3/embeddings/models`.

## Speech-to-text

<CodeGroup>
```bash .env
AUDIO_STT_ENGINE=openai
AUDIO_STT_MODEL=groq/whisper-large-v3-turbo
AUDIO_STT_OPENAI_API_BASE_URL=https://api.edenai.run/v3
AUDIO_STT_OPENAI_API_KEY=YOUR_API_KEY
```
</CodeGroup>

On an existing install, use **Admin Panel**, **Settings**, **Audio**, **Speech-to-Text Engine**. Open WebUI posts the audio to `/audio/transcriptions` under that base URL, which Eden AI serves. See [Speech to Text](/v3/llms/speech-to-text).

## Image generation

<CodeGroup>
```bash .env
ENABLE_IMAGE_GENERATION=true
IMAGE_GENERATION_ENGINE=openai
IMAGE_GENERATION_MODEL=openai/gpt-image-2
IMAGES_OPENAI_API_BASE_URL=https://api.edenai.run/v3
IMAGES_OPENAI_API_KEY=YOUR_API_KEY
IMAGE_SIZE=1024x1024
```
</CodeGroup>

Open WebUI's default size is `512x512`, and OpenAI's image models accept `1024x1024`, `1536x1024`, `1024x1536` or `auto`, so set `IMAGE_SIZE` as shown. On an existing install, use **Admin Panel**, **Settings**, **Images**.

In a chat, turn on the **Image** toggle in the message box's integrations menu, then send a prompt. See [Image Generation](/v3/llms/image-generation).

## Web Search

Open WebUI's **Perplexity Search** engine works with Eden AI's [Perplexity-compatible search API](/v3/llms/search-api). The engine sends a fixed body with no `model`, so the provider goes in the URL path:

1. Open **Admin Panel**, then **Settings**, then **Web Search**.
2. Turn on the **Web Search** toggle and select `perplexity_search` as the **Web Search Engine**.
3. Enter your Eden AI API key in **Perplexity API Key**.
4. Set **Perplexity Search API URL** to `https://api.edenai.run/v3/search/tavily` (or end it with another provider `id` from `GET /v3/search/models`).

On a new install, you can set the same values through environment variables instead:

<CodeGroup>
```bash .env
ENABLE_WEB_SEARCH=true
WEB_SEARCH_ENGINE=perplexity_search
PERPLEXITY_API_KEY=YOUR_API_KEY
PERPLEXITY_SEARCH_API_URL=https://api.edenai.run/v3/search/tavily
```
</CodeGroup>

<Warning>
Keep the search result count (`WEB_SEARCH_RESULT_COUNT`, default 3) at 20 or below. Eden AI rejects a larger `max_results`, and Open WebUI hides the error: searches return no results and no message says why.
</Warning>

Each query Open WebUI sends is a billed search on your Eden AI account, and Open WebUI can generate more than one query for a single chat message. `GET /v3/search/models` lists each provider's price.

## Troubleshooting

### Models do not appear

1. Check the connection: **Admin Panel**, **Settings**, **Connections**, **OpenAI API** must list `https://api.edenai.run/v3` with your key. On an existing install the environment variables are ignored (see the note under Setup).
2. Test the key outside Open WebUI:
   ```bash
   curl -X POST https://api.edenai.run/v3/chat/completions \
     -H "Authorization: Bearer YOUR_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "model": "anthropic/claude-sonnet-latest",
       "messages": [{"role": "user", "content": "test"}],
       "stream": true
     }'
   ```
3. On an existing install, change the values in the Admin Panel. To make Open WebUI read the environment again, set `ENABLE_PERSISTENT_CONFIG=false` and recreate the container (`docker rm -f open-webui`, then the `docker run` command again). `docker restart` keeps the old environment.

### Embeddings, audio or images fail while chat works

Each feature has its own base URL and key. If `RAG_OPENAI_API_BASE_URL`, `AUDIO_STT_OPENAI_API_BASE_URL` or `IMAGES_OPENAI_API_BASE_URL` is not set to `https://api.edenai.run/v3`, Open WebUI sends that feature to `api.openai.com` with an empty key. Check the matching page in **Admin Panel**, **Settings**: **Documents**, **Audio** or **Images**.

### Web search returns nothing

Check that **Perplexity Search API URL** ends with a provider from `GET /v3/search/models` and that the result count is 20 or below.
