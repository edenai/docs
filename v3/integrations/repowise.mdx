[Repowise](https://github.com/repowise-dev/repowise) indexes a repository into code health scores, generated documentation and git analytics. It has a built-in `edenai` provider for both the LLM and the embedder, so one Eden AI key covers both.

## Overview

With Eden AI as the provider:

- **500+ models**: reach OpenAI, Anthropic, Google, Mistral and more through one key
- **LLM and embedder from the same key**: no second account for embeddings
- **EU endpoint**: `EDENAI_BASE_URL` covers both the LLM and the embedder in one setting

## Prerequisites

- Repowise installed: `uv tool install repowise` (or `pipx install repowise`, `pip install repowise`). See the [Repowise repository](https://github.com/repowise-dev/repowise)
- An Eden AI API key from [app.edenai.run](https://app.edenai.run) → **API Keys**

## Setup

### 1. Export your key

<CodeGroup>
```bash Terminal
export EDENAI_API_KEY="YOUR_API_KEY"
```
</CodeGroup>

### 2. Initialise with Eden AI

Always pass `--provider edenai`. Repowise detects Eden AI last, after any other provider key it recognises, such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`, so if one of those is also set, auto-detection picks that provider instead.

<CodeGroup>
```bash Terminal
repowise init --provider edenai --model mistral/mistral-small-latest
```
</CodeGroup>

Reasoning models are supported with an explicit effort level:

<CodeGroup>
```bash Terminal
repowise init --provider edenai --model openai/gpt-5-mini --reasoning low
```
</CodeGroup>

Repowise sends the reasoning effort only for OpenAI ids whose model name starts with `gpt-5`, `o1`, `o3` or `o4`, so use the version-named id here. With an alias such as `openai/gpt-mini-latest`, Repowise offers no reasoning levels for the model and `init` fails with `Provider validation failed` when you pass `--reasoning`.

## Model naming

Eden AI addresses models as `vendor/model`, and Repowise passes the identifier through unchanged. For example `mistral/mistral-small-latest` or `vertex/gemini-flash-latest`. See [List LLM Models](/v3/llms/listing-models) for the full list. The live catalogues are public and need no key:

<CodeGroup>
```bash Chat models
curl https://api.edenai.run/v3/models
```

```bash Embedding models
curl https://api.edenai.run/v3/embeddings/models
```
</CodeGroup>

<Note>
  The chat and embedding catalogues are **separate endpoints**. An embedding model will not appear in `/v3/models`, which is a common source of confusion when picking one.
</Note>

## Embeddings for semantic search

Select the embedder explicitly, for the same reason as the LLM: Eden AI is detected last, so a Gemini, OpenAI or OpenRouter key (or `OLLAMA_EMBEDDING_MODEL`) in the environment wins otherwise.

<CodeGroup>
```bash Terminal
repowise init --provider edenai --embedder edenai
```
</CodeGroup>

`--embedder` accepts `edenai` alongside `openai`, `gemini`, `ollama`, `openrouter` and `mock`. You can also set `REPOWISE_EMBEDDER=edenai`. Pick the embedding model with `REPOWISE_EMBEDDING_MODEL`:

<CodeGroup>
```bash .env
export EDENAI_API_KEY="YOUR_API_KEY"
export REPOWISE_EMBEDDER="edenai"
export REPOWISE_EMBEDDING_MODEL="google/gemini-embedding-001"
```
</CodeGroup>

Repowise accepts only embedding models whose vector width it knows. The default is Amazon Titan Text Embeddings v2, and `google/gemini-embedding-001` and `openai/text-embedding-3-small` are among the others (the full set is in Repowise's `EdenAIEmbedder._DIMS`). For any other id, Repowise prints a warning containing `Unknown embedding model` and falls back to keyless embeddings, so the run finishes without semantic search, even when Eden AI serves the model. Browse the models Eden AI serves in the embeddings catalogue above.

<Note>
  A model's vector width is a property of the gateway serving it, not of the model name alone. The same identifier can return a different number of dimensions through two different gateways, so use the width Repowise records for Eden AI rather than copying a figure from another provider's table.
</Note>

## EU data residency

One variable covers both the LLM and the embedder:

<CodeGroup>
```bash .env
export EDENAI_API_KEY="YOUR_API_KEY"
export EDENAI_BASE_URL="https://api.eu.edenai.run/v3"
```
</CodeGroup>

The EU endpoint serves a subset of the catalogue, so a model that works on the global endpoint is not guaranteed to be reachable through it. Its catalogues were checked on 2026-10-27:

- **Chat**: `mistral/mistral-small-latest` (the Repowise default) and `vertex/gemini-flash-latest` are served. `openai/gpt-latest`, `anthropic/claude-sonnet-latest` and `openai/gpt-5-mini` are not, so skip the reasoning example above on this endpoint.
- **Embeddings**: leave `REPOWISE_EMBEDDING_MODEL` unset, because the default (Amazon Titan Text Embeddings v2) is served, or set the EU-served `amazon/cohere.embed-multilingual-v3`:

<CodeGroup>
```bash .env
export REPOWISE_EMBEDDING_MODEL="amazon/cohere.embed-multilingual-v3"
```
</CodeGroup>

The other models Repowise accepts, including `google/gemini-embedding-001`, are not in the EU embeddings catalogue.

Check the current lists with `curl https://api.eu.edenai.run/v3/models` and `curl https://api.eu.edenai.run/v3/embeddings/models`.

## Troubleshooting

### `401 Unauthorized`

Check that `EDENAI_API_KEY` is exported in the shell Repowise runs from, and that the value is an Eden AI key rather than a vendor key. Eden AI answers `Invalid API key` for a wrong or revoked `sk-eden-...` key, and `Invalid token` for any other token shape.

### `model not found`

Copy the identifier exactly as the catalogue returns it, vendor prefix included, and make sure you read the right catalogue: chat models from `/v3/models`, embedding models from `/v3/embeddings/models`. On the EU endpoint, read the EU catalogues.

### `Unknown embedding model`

Repowise did not accept `REPOWISE_EMBEDDING_MODEL`, warned, and carried on with keyless embeddings. Set one of the models it accepts, listed in the embeddings section above, then run `repowise reindex`.

### Semantic search returns nothing useful

Confirm the embedder actually resolved to `edenai` rather than falling back. With no embedder set and no recognised key, or with an embedder that could not be built (an unaccepted model, a missing key), Repowise degrades to keyless embeddings, which index without producing real vectors.
