Run many requests as one asynchronous batch. You upload a file with one request per line, Eden AI runs the whole batch on the provider at the provider's batch rates, and you read the results when the batch has finished.

## Providers and endpoints

| Provider | Model id on every line | `url` on every line |
|---|---|---|
| OpenAI | `openai/<model>` | `/v1/chat/completions` |
| Anthropic | `anthropic/<model>` | `/v1/chat/completions` |
| Mistral | `mistral/<model>` | `/v1/chat/completions` |
| Amazon Bedrock | `amazon/<model>@eu` | `/v1/chat/completions` |
| Vertex AI | `vertex/<model>@eu` | `/v1/chat/completions` |

A batch has one model and one `url`: every line names the same model and calls the same endpoint. In [`GET /v3/models`](/v3/llms/listing-models), `capabilities.supports_batch` is `true` on each entry a batch accepts. Image, audio and other endpoints are not available in a batch.

Every provider's batch is created, listed, cancelled and read through the same routes. Chat lines use the chat completions format on every provider, and so do their results: an Anthropic, Amazon Bedrock or Vertex AI result is translated to a chat completion.

### Regions

Amazon Bedrock and Vertex AI batches run in the EU, so the model is named with its region tag, `amazon/<model>@eu` or `vertex/<model>@eu`. Without the tag the batch is refused with `400`. A batch on OpenAI, Anthropic or Mistral runs in the provider's default region, and a model named with a region tag is refused with `400`.

## Overview

All routes are under `https://api.edenai.run/v3/batches` and use the same `Authorization: Bearer YOUR_API_KEY` header as the rest of the API.

| Route | Purpose |
|---|---|
| `POST /v3/batches` | Create a batch from a JSONL file. |
| `GET /v3/batches` | List your batches, newest first. |
| `GET /v3/batches/{batch_id}` | Get the status, request counts and cost of one batch. |
| `POST /v3/batches/{batch_id}/cancel` | Cancel a batch. |
| `GET /v3/batches/{batch_id}/results` | Download the results as JSONL. |

A batch that belongs to another account, or that does not exist, answers `404`.

`/v3/batches` is the only batch API. The V2 API has none: its `/v2/{feature}/{subfeature}/batch/{name}/` route runs each line as its own separate feature call and does not use a provider's batch endpoint.

A sandbox token sends nothing to the provider: the batch is answered at once with sample results and is not billed.

## Input file

The input is a JSONL file: one JSON object per line, in UTF-8. Empty lines are ignored. Each line describes one request:

```json
{"custom_id": "request-1", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "openai/gpt-5-mini", "messages": [{"role": "user", "content": "Say hello in French."}], "max_completion_tokens": 50}}
```

| Field | Rules |
|---|---|
| `custom_id` | Required. A non-empty string, unique within the file. Results carry it back so you can match each answer to its request. |
| `method` | Required. Must be `"POST"`. |
| `url` | Required. `"/v1/chat/completions"`, the same on every line. |
| `body` | Required. A chat completion body, with the fields of [Chat Completions](/v3/llms/chat-completions) and the restrictions below. |

No other key is allowed on a line.

### Rules for every chat line

- `body.model` is `openai/<model>`, `anthropic/<model>` or `mistral/<model>` with no `@` or `:` suffix, or `amazon/<model>@eu` or `vertex/<model>@eu`. Every line of a batch names the same model.
- The model must have published batch rates. Models without them, models that price long-context bands, and models that price cached input without a cached batch rate are refused, except that cached input needs no cached batch rate on Amazon Bedrock. Models that price cache writes or audio are refused too, except that cache-write rates do not refuse an Anthropic or Amazon Bedrock model (their lines carry no cache marker) and audio rates do not refuse a Vertex AI model (its lines are text only).
- In [`GET /v3/models`](/v3/llms/listing-models), `capabilities.supports_batch` is `true` on each entry a batch accepts, by the same rules.
- Messages carry text only. A `content` list may contain `text` parts only.
- `max_tokens` or `max_completion_tokens` on each line sets how much output Eden AI reserves for that line. Without either, the reservation uses the model's maximum output. See [Billing](#billing). A `max_tokens` is sent to OpenAI as `max_completion_tokens`, which every OpenAI chat model takes; GPT-5 and o-series models refuse `max_tokens` in a batch.
- On Anthropic, Mistral, Amazon Bedrock and Vertex AI, a line that states no output limit is sent with the reserved bound as its `max_tokens`. `max_tokens` applies to each completion, so a Mistral line with `n` above 1 is sent the reserved bound divided by `n`.
- An output limit is checked as the provider's own API documents it, and a value the provider refuses fails the file with `400` naming the line. Anthropic takes a number of 0 or more, Mistral an integer of 0 or more, Vertex AI an integer, and Amazon Bedrock an integer of 1 or more.
- A line that states both `max_tokens` and `max_completion_tokens` is reserved at the first one that is a positive integer, `max_tokens` first, and on Anthropic, Amazon Bedrock and Vertex AI that value is the one sent. A limit that is not a positive integer, such as `512.0`, reserves the model's maximum output, and on Anthropic and Mistral it is sent capped at that reservation, a whole number written as an integer (`512.0` is sent as `512`).
- `service_tier`, when present on an OpenAI line, is `auto` or `default`.
- `routing` may only contain `zero_data_retention`. See [Zero data retention](#zero-data-retention).
- Every line is moderated. See [Content moderation](#content-moderation).

A batch prices prompt and completion tokens only, so an OpenAI line's `body` may carry these fields and no others: `model`, `messages`, `n`, `max_tokens`, `max_completion_tokens`, `temperature`, `top_p`, `stop`, `seed`, `presence_penalty`, `frequency_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `response_format`, `reasoning_effort`, `verbosity`, `user`, `service_tier`, `stream` (false only), `prompt_cache_key` and `routing`. Any other field, such as `tools`, `web_search_options`, `audio` or `modalities`, is refused with `400` naming the line and the field.

These body fields are refused on every provider: `stream` set to true, `tools`, `functions`, `function_call`, `prediction`, `fallbacks`, `router_candidates`, `pre_hooks`, `post_hooks`, `session_id`, `tags`, `extra_headers` and `extra_body`. Fields that set the provider connection or how a call is priced, such as `api_key` and `api_base`, are refused as in any other request.

### What each provider accepts on a chat line

| Provider | Body fields accepted | Refused |
|---|---|---|
| OpenAI | The fields listed above. A message holds `role`, `content` and optionally `cache_control`. `service_tier` is `auto` or `default`. | A `service_tier` of `flex`, `scale` or `priority`, any other body field, and any other message key such as `tool_calls`. |
| Anthropic | `model`, `messages`, `max_tokens`, `max_completion_tokens`, `temperature`, `top_p`, `stop`, `user`, `reasoning_effort`, `thinking` and `routing`. A message holds `role` and `content`, and a text part holds `type` and `text`. `thinking.budget_tokens` is below the line's output limit. | Every other body field, among them `n`, `logprobs`, `response_format` and `service_tier`, and `cache_control` on a message or a part. |
| Mistral | `model`, `messages`, `max_tokens`, `temperature`, `top_p`, `stop`, `n`, `presence_penalty`, `frequency_penalty`, `response_format` and `routing`. A message holds `role` and `content`, with the role `system`, `user` or `assistant`, and a text part holds `type` and `text`. | Every other body field, among them `max_completion_tokens`, `seed`, `logit_bias`, `user`, `top_logprobs`, `stream_options` and `service_tier`, a message `name`, and `cache_control`. |
| Amazon Bedrock | `model`, `messages`, `max_tokens`, `max_completion_tokens`, `temperature`, `top_p`, `stop` and `routing`. A message holds `role` and `content`, with the role `system`, `user` or `assistant`, and a text part holds `type` and `text`. System messages come first, the conversation starts and ends with a user message, and every message carries text. `temperature` and `top_p` are between 0 and 1, and `stop` holds at most 4 sequences. | Every other body field, among them `n`, `response_format`, `user` and `service_tier`, a message `name`, and `cache_control`. |
| Vertex AI | `model`, `messages`, `max_tokens`, `max_completion_tokens`, `temperature`, `top_p`, `stop` and `routing`. A message holds `role` and `content`, with the role `system`, `user` or `assistant`, and a text part holds `type` and `text`. System messages come first, the conversation ends with a user message, and every message carries text. `temperature` is between 0 and 2 and `top_p` between 0 and 1. | Every other body field, among them `n`, `response_format`, `user` and `service_tier`, a message `name`, and `cache_control`. |

A refused field fails the whole file with `400` and the message `Line N: ...` naming the field.

An Anthropic line has the same shape as any chat line, with an `anthropic/` model and the fields from the table above:

```json
{"custom_id": "request-1", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "anthropic/claude-haiku-4-5", "messages": [{"role": "user", "content": "Say hello in French."}], "max_tokens": 50}}
```

### File limits

A batch holds at most 5,000 lines, and the file is at most 100 MB. A file with more than 5,000 requests is refused with `400`, and so is a file with no request.

An Amazon Bedrock batch needs at least 100 lines, the minimum AWS sets for every job. A smaller file is refused with `400`. No other provider has a minimum.

## Create a batch

Send the file as `multipart/form-data`.

| Form field | Required | Description |
|---|---|---|
| `file` | yes | The JSONL input file. |
| `metadata` | no | A JSON object of string pairs, sent as text. Up to 14 pairs, keys up to 64 characters, values up to 512 characters. On a Mistral batch, keys are at most 32 characters and values at least one. The keys `eden_batch_id` and `eden_request_id` are reserved. |
| `webhook_receiver` | no | A URL Eden AI calls once the batch has finished and settled. See [Webhooks](#webhooks). |

<CodeGroup>
```python Python
import json
import requests

lines = [
    {
        "custom_id": f"request-{i}",
        "method": "POST",
        "url": "/v1/chat/completions",
        "body": {
            "model": "openai/gpt-5-mini",
            "messages": [{"role": "user", "content": f"Write a one-line tagline for product {i}."}],
            "max_completion_tokens": 50,
        },
    }
    for i in range(1, 4)
]
with open("batch.jsonl", "w", encoding="utf-8") as f:
    for line in lines:
        f.write(json.dumps(line) + "\n")

url = "https://api.edenai.run/v3/batches"
headers = {"Authorization": "Bearer YOUR_API_KEY"}

with open("batch.jsonl", "rb") as f:
    response = requests.post(
        url,
        headers=headers,
        files={"file": ("batch.jsonl", f, "application/jsonl")},
        data={"metadata": json.dumps({"project": "taglines"})},
        timeout=(10, 120),
    )

batch = response.json()
print(batch["id"], batch["status"])
```

```bash cURL
curl -X POST https://api.edenai.run/v3/batches \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@batch.jsonl" \
  -F 'metadata={"project": "taglines"}'
```
</CodeGroup>

The response is the batch object:

```json
{
  "id": "6f1c2d3e-8a4b-4c5d-9e6f-7a8b9c0d1e2f",
  "object": "batch",
  "endpoint": "/v1/chat/completions",
  "model": "openai/gpt-5-mini",
  "status": "validating",
  "request_counts": {"total": 3, "completed": 0, "failed": 0},
  "metadata": {"project": "taglines"},
  "created_at": 1790000000,
  "finished_at": null,
  "cost": null,
  "error": null,
  "results_available": false
}
```

| Field | Description |
|---|---|
| `id` | The batch id. Use it in every other route. |
| `endpoint` | The `url` every line calls. |
| `model` | The model every request runs on, as the lines name it. |
| `status` | Where the batch is in its lifecycle. See [Statuses](#statuses). |
| `request_counts` | `total`, `completed` and `failed` requests, refreshed every few minutes. |
| `metadata` | The pairs you sent at create. |
| `created_at`, `finished_at` | Unix timestamps in seconds. `finished_at` is `null` until the batch has finished and settled. |
| `cost` | What the batch billed, in US dollars. `null` until the batch has finished. |
| `error` | Why the batch failed, when it did. |
| `results_available` | `true` when [the results](#results) can be read: the batch has finished, was created at the provider, the provider ended it, and it was created less than 30 days ago (less one hour). `false` while it runs, for a batch that ended before the provider accepted it, and once that window has passed. Read from the stored batch with no call to the provider: a batch settled at [the 25-hour limit](#the-24-hour-window) before the provider ended it reads `false`, and the results route checks the provider and can still serve it. A sandbox batch reads `true` once it has finished. |

### Create from an uploaded file

The create route also takes the JSON body the OpenAI SDK's `batches.create` sends. Upload the JSONL file with [`POST /v3/upload`](/v3/llms/file-upload), then send its `file_id` as `input_file_id`. The OpenAI SDK's `files.create` has no route here: upload through `/v3/upload` instead.

| Field | Required | Description |
|---|---|---|
| `input_file_id` | yes | The `file_id` returned by `POST /v3/upload`. |
| `endpoint` | no | `/v1/chat/completions`, the only value accepted. |
| `completion_window` | no | `24h`, the only value accepted. |
| `metadata` | no | A JSON object of string pairs, with the same limits as the form field. |
| `webhook_receiver` | no | A URL Eden AI calls once the batch has finished and settled. |

The file goes through the same checks as one sent in the form. A file id that does not exist, has expired, or belongs to another user answers `404`, and so does a file whose stored content can no longer be read: upload it again. A stored file larger than 100 MB answers `413`, and a file that is not JSONL answers `400`. Another `completion_window`, an `endpoint` outside the three above, or an `endpoint` other than the one the lines call answers `400`.

```python Python
from openai import OpenAI
import requests

headers = {"Authorization": "Bearer YOUR_API_KEY"}

with open("batch.jsonl", "rb") as f:
    upload = requests.post(
        "https://api.edenai.run/v3/upload",
        headers=headers,
        files={"file": ("batch.jsonl", f, "application/jsonl")},
        timeout=(10, 120),
    ).json()

client = OpenAI(api_key="YOUR_API_KEY", base_url="https://api.edenai.run/v3")
batch = client.batches.create(
    input_file_id=upload["file_id"],
    endpoint="/v1/chat/completions",
    completion_window="24h",
    metadata={"project": "taglines"},

print(batch.id, batch.status)
```


## List batches

`GET /v3/batches` returns your batches, newest first.

| Query parameter | Description |
|---|---|
| `limit` | Batches per page, from 1 to 100. Defaults to 20. |
| `after` | The `last_id` of the previous page. An unknown id answers `404`. |
| `model` | Only the batches run on this model (`<provider>/<model>`, such as `anthropic/<model>`), including those whose lines named one of its aliases. A value without a `/` answers `422`. |

The response holds `data` (the batch objects), `first_id`, `last_id` and `has_more`.

<CodeGroup>
```python Python
import requests

url = "https://api.edenai.run/v3/batches"
headers = {"Authorization": "Bearer YOUR_API_KEY"}

page = requests.get(url, headers=headers, params={"limit": 10}, timeout=30).json()
for batch in page["data"]:
    print(batch["id"], batch["status"])

if page["has_more"]:
    next_page = requests.get(
        url,
        headers=headers,
        params={"limit": 10, "after": page["last_id"]},
        timeout=30,
    ).json()
```

```bash cURL
curl "https://api.edenai.run/v3/batches?limit=10" \
  -H "Authorization: Bearer YOUR_API_KEY"
```
</CodeGroup>

## Cancel a batch

`POST /v3/batches/{batch_id}/cancel` asks the provider to stop the batch. The response is the batch object, and its status reads `cancelling` until the provider has stopped it, then `cancelled`.

Requests that completed before the cancel are billed, and their results stay available. A batch that has already finished answers `400`.

## Results

`GET /v3/batches/{batch_id}/results` streams the results as JSONL (`application/jsonl`), one line per request. On OpenAI, results stay available for 30 days after the batch finished. On Anthropic, they stay available for 29 days after the batch was created. Mistral states that batch results do not expire. Amazon Bedrock and Vertex AI results are read from Eden AI's own storage. Once the provider no longer has them, the route answers `410`.

A request that succeeded carries `response`, with the `status_code` and the chat completion `body`, on every provider. The `model` in the body is the Eden AI id you sent, such as `openai/<model>`. A request that failed carries `error` instead.

```json
{"custom_id":"request-1","response":{"status_code":200,"body":{"id":"chatcmpl-abc123","object":"chat.completion","model":"openai/gpt-5-mini","choices":[{"index":0,"message":{"role":"assistant","content":"Bonjour !"},"finish_reason":"stop"}],"usage":{"prompt_tokens":14,"completion_tokens":3,"total_tokens":17}}},"error":null}
```

Match results to requests with `custom_id`. Do not rely on the order of the lines.

{/* skip-test: BATCH_ID is a placeholder, and results exist only once a batch has finished */}
<CodeGroup>
```python Python
import json
import requests

batch_id = "BATCH_ID"
url = f"https://api.edenai.run/v3/batches/{batch_id}/results"
headers = {"Authorization": "Bearer YOUR_API_KEY"}

with requests.get(url, headers=headers, stream=True, timeout=(10, 300)) as response:
    response.raise_for_status()
    for raw in response.iter_lines():
        if not raw:
            continue
        result = json.loads(raw)
        if result["error"] is None:
            body = result["response"]["body"]
            print(result["custom_id"], body["choices"][0]["message"]["content"])
        else:
            print(result["custom_id"], "failed:", result["error"])
```

```bash cURL
curl https://api.edenai.run/v3/batches/BATCH_ID/results \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -o results.jsonl
```
</CodeGroup>

The results route answers `400` while the batch is still running, and `409` when the batch is finished on Eden AI's side but the provider has not yet ended it. Retry after a short wait.

## Statuses

| Status | Meaning |
|---|---|
| `validating` | The batch was created and is waiting to start. |
| `in_progress` | The requests are running. |
| `finalizing` | The requests are done and the results are being prepared. |
| `completed` | The batch finished. Individual requests can still have failed, so read each line. |
| `failed` | The batch failed as a whole. Any request that completed before the failure is billed. |
| `expired` | The batch did not finish within its 24-hour window. Requests that completed are billed and their results are available. |
| `cancelling` | A cancel was requested and the provider is stopping the batch. |
| `cancelled` | The batch was cancelled. Requests that completed are billed. |

An Amazon Bedrock job that ends with some requests left unprocessed reads `expired`. A Vertex AI job that partly succeeded reads `completed`, and a paused one reads `in_progress`.

`cost` and `finished_at` are filled in once the batch has finished and Eden AI has settled it. That can be a few minutes after the status reaches a final value.

## The 24-hour window

If the batch has not finished 25 hours after it was created, Eden AI cancels it, bills the requests that completed and makes their results available. Cancel a batch yourself at any time before that.

## Billing

Batches are billed at the model's batch rates for input tokens, output tokens and, when the model has one, cached input tokens. These rates are lower than the standard rates of the same model.

The rates are in the `pricing` object of each model in [`GET /v3/models`](/v3/llms/listing-models) as `input_cost_per_token_batches`, `output_cost_per_token_batches` and `cache_read_input_token_cost_batches`, in US dollars per token. A model whose entry has no input and output batch rate cannot be batched.

### In your usage

The batch shows in [usage monitoring](/v3/general/monitoring) as cost. The launch records the reservation and the settlement adds the difference between the final cost and the reservation, so the total is what the batch was charged. The settlement is not counted as a request or as tokens.

- **At create.** Eden AI reserves the largest amount the batch could cost and deducts it from your balance. For each line, the reservation covers the prompt tokens plus the line's `max_tokens` (or `max_completion_tokens`, or the model's maximum output when neither is set), multiplied by `n`. If your balance or a member budget cannot cover it, the request answers `402` and nothing is sent.
- **At the end.** The batch is settled once, from the results. Each request that succeeded bills the tokens the provider reports it used. A request that failed, was cancelled or expired bills nothing. A request that succeeded but reports no usage, or that the provider counts as completed but that has no line in the results, bills an estimate: its prompt tokens, plus the output its response shows and 8,192 tokens per completion, never more output than was reserved for it. The difference between the reservation and the final cost is returned to your balance.
- **When nothing completed.** The batch bills nothing and the whole reservation is returned.
- **When results cannot be read.** Each request that may have run bills the same estimate, with no output shown. For a batch that has ended, that is as many requests as the provider counts as completed, the largest estimates first. Otherwise it is every request. A batch with a request that may have run is never settled at zero.

Set `max_completion_tokens` on every line to keep the reservation close to the real cost.

## Content moderation

Eden AI checks the text of every line before the batch is sent, `response_format` included. Sampling does not apply, and the `bypass_moderation` setting does not skip the check.

| Outcome | Result |
|---|---|
| A line is flagged | The whole batch is refused with `400`, naming the flagged lines. Nothing is sent and nothing is charged. |
| The moderation service rejects the content of a line | The batch is refused with `400`, naming the lines. |
| The check could not run | The batch is refused with `503`. Nothing is sent and nothing is charged. Retry. |

## Zero data retention

A batch is judged as a call that keeps its data at the provider, so batches cannot honor zero data retention on any provider. A batch is refused when your organization requires zero data retention (`403`) or when a line sets `routing.zero_data_retention` (`400`). A region restriction (`allowed_regions`) that excludes the region the batch runs in is refused with `451`.

## Your own provider key

Batches run on Eden AI's account at the provider only. If your organization has added its own key for the batch's provider, create requests are refused with `400`.

## Webhooks

Pass `webhook_receiver` at create to be notified instead of polling. Eden AI sends a signed `POST` to the URL once the batch has finished and settled. The signature, headers and verification steps are the ones described in [Webhooks](/v3/expert-models/webhooks).

The notification reports `success` for a `completed` batch and `fail` for any other final status. It does not carry the results: read them from the results route.

The payload has the shape of every Eden AI job notification. `job_id` is the batch `id`, and `feature` and `subfeature` are `llm` and `batch`:

```json
{
  "event": "async_job_completed",
  "job_id": "6f1c2d3e-8a4b-4c5d-9e6f-7a8b9c0d1e2f",
  "status": "success",
  "feature": "llm",
  "subfeature": "batch",
  "provider": "openai",
  "model": "gpt-5-mini",
```

| Field | Description |
|---|---|
| `job_id` | The batch `id`. Use it with `GET /v3/batches/{batch_id}` and the results route. |
| `status` | `success` or `fail`. |
| `model` | The provider's model name. `output.model` holds the Eden AI id you sent. |
| `created_at`, `finished_at` | ISO 8601 timestamps. The batch object gives the same times in Unix seconds. |
| `output` | On `success`: the provider's last reported status of the batch (`batch_status`), its request counts and your metadata. Absent on `fail`. |
| `error` | On `fail`: `{"message": "..."}`, the same text as the batch's `error`. Absent on `success`. |

To fetch the results when the notification arrives, read `job_id` and call the results route:

{/* skip-test: the payload comes from a webhook delivery */}
```python Python
import requests


def on_batch_notification(payload: dict) -> None:
    batch_id = payload["job_id"]
    succeeded = payload["status"] == "success"
    if not succeeded:
        # A cancelled or expired batch keeps the results of the requests that completed.
        print(batch_id, "failed:", payload["error"]["message"])
    url = f"https://api.edenai.run/v3/batches/{batch_id}/results"
    headers = {"Authorization": "Bearer YOUR_API_KEY"}
    with requests.get(url, headers=headers, stream=True, timeout=(10, 300)) as response:
        if not succeeded and not response.ok:
            print(batch_id, "has no results:", response.status_code)
            return
        response.raise_for_status()
        with open(f"{batch_id}.jsonl", "wb") as f:
            for chunk in response.iter_content(chunk_size=65536):
                f.write(chunk)
```

The URL must be public. Addresses that resolve to private networks are refused.

## Limits and what batches do not do

- A batch holds at most 5,000 lines and 100 MB, and an Amazon Bedrock batch at least 100 lines.
- A batch runs one model, on OpenAI, Anthropic, Mistral, Amazon Bedrock or Vertex AI. Other providers are not supported.
- Chat completions are supported on all five providers. Other endpoints are not.
- Lines cannot stream.
- Lines cannot carry tools, function definitions, function calls or predicted outputs.
- Lines cannot carry images, audio or files. Messages are text only.
- Batches run on Eden AI's provider accounts. Your own provider keys are not used.
- Fallbacks, hooks, sessions and tags are not available on a line.

## Errors

| Status | Meaning |
|---|---|
| `400` | The file or a line is invalid. The message names the line, for example `Line 3: ...`. Also returned for a model that is not in the catalog or cannot be batched, an Amazon Bedrock or Vertex AI model named without `@eu`, an Amazon Bedrock file under 100 lines, a flagged line, a zero data retention request, an organization with its own key for the provider, and for cancelling or reading results of a batch in the wrong state. |
| `401` | Missing or invalid `Authorization: Bearer` token. |
| `402` | The balance is zero or less (checked before the file is read), the balance or a member budget cannot cover the reservation, or the reservation is $100,000 or more, which is refused whatever the balance. Add credits, or raise the member budget, when the balance or budget is short; split the file into smaller batches when the reservation reaches $100,000. |
| `403` | Your organization requires zero data retention, or a [guardrail](/v3/organization/guardrails) model rule does not allow the model: `Model(s) 'openai/...' not allowed by your guardrail policy.` |
| `404` | The batch does not exist or is not yours. |
| `409` | The batch was never created at the provider, so it cannot be cancelled or read. Also returned by results while the provider has not ended the batch. |
| `410` | The batch's results are no longer kept by the provider. |
| `413` | The file is larger than 100 MB. |
| `422` | `metadata` is not a JSON object of strings, holds too many pairs, or uses a reserved key, or the JSON create body carries a field it does not define. |
| `429` | Content moderation refused three of your batches within the last hour. Retry after the hour. |
| `451` | A region restriction excludes the region the batch runs in. |
| `503` | Batches are temporarily unavailable, moderation could not run, or billing is unavailable. Nothing was charged. Retry later. |

When the provider fails a create, cancel or results call, the error status it returned is passed on with its message.
