Generate and edit images through Eden AI's OpenAI-compatible image endpoints. Point any OpenAI client at `https://api.edenai.run/v3` and the images API works as a drop-in replacement.

## Overview

Image models are served by dedicated image endpoints — **not** the chat completions endpoint:

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/v3/images/generations` | Generate one or more images from a text prompt |
| `POST` | `/v3/images/edits` | Edit an existing image with a prompt (optional mask) |
| `GET`  | `/v3/images/models` | List the image models available in your region |

Both endpoints return the standard OpenAI image shape — `data: [{ url \| b64_json }]` — plus Eden's `cost` (USD) and `provider` fields.

<Warning>
Image models are only available on `/v3/images/*`. Sending one to `/v3/chat/completions` returns `400 — Model(s) do not support /chat/completions`.
</Warning>

<Info>
This is different from [Expert Model image generation](/v3/expert-models/features/image/generation), which wraps Eden's feature API for providers like DALL-E and Stable Diffusion. Use the `/v3/images` endpoints when you want an OpenAI-compatible, drop-in image surface.
</Info>

## Models

The image surface spans many providers. A few common model strings:

| Provider | Model string |
|---|---|
| Google | `vertex/gemini-2.5-flash-image`, `vertex/gemini-3-pro-image`, `vertex/gemini-3.1-flash-image` |
| OpenAI | `openai/gpt-image-1`, `openai/gpt-image-1-mini` |
| Stability | `stabilityai/sd3.5-large` |
| Amazon | `amazon/amazon.nova-canvas-v1:0` |

Call `GET /v3/images/models` for the full, region-aware list (image models also appear in `GET /v3/models`, so the OpenAI SDK's `client.models.list()` returns them too).

## Generating images

<CodeGroup>
```python Python
import requests

url = "https://api.edenai.run/v3/images/generations"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
}

payload = {
    "model": "vertex/gemini-2.5-flash-image",
    "prompt": "A nano banana dish in a fancy restaurant, cinematic lighting",
    "size": "1024x1024",
    "n": 1,
}

response = requests.post(url, headers=headers, json=payload)
result = response.json()

# Each item carries either a hosted `url` or an inline base64 `b64_json`
image = result["data"][0]
print(image["url"] or image["b64_json"][:60])
```

```bash cURL
curl -X POST https://api.edenai.run/v3/images/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "vertex/gemini-2.5-flash-image",
    "prompt": "A nano banana dish in a fancy restaurant, cinematic lighting",
    "size": "1024x1024",
    "n": 1
  }'
```
</CodeGroup>

Because the surface is OpenAI-compatible, the official OpenAI SDK works unchanged — just set `base_url`:
<CodeGroup>
```python OpenAI SDK
from openai import OpenAI

client = OpenAI(base_url="https://api.edenai.run/v3", api_key="YOUR_API_KEY")

result = client.images.generate(
    model="vertex/gemini-2.5-flash-image",
    prompt="A nano banana dish in a fancy restaurant, cinematic lighting",
    size="1024x1024",
    n=1,
)
print(result.data[0].url or result.data[0].b64_json[:60])
```
</CodeGroup>

### Request parameters

| Field | Required | Description |
|---|---|---|
| `model` | yes | `provider/model`, e.g. `vertex/gemini-2.5-flash-image` |
| `prompt` | yes | Text description of the image to generate (1–32,000 chars) |
| `n` | no | Number of images to generate (1–10) |
| `size` | no | Output resolution, e.g. `1024x1024`, `1536x1024`, `auto`. Allowed values depend on the model |
| `quality` | no | `standard`, `hd`, `auto` — accepted values depend on the model |
| `response_format` | no | `url` or `b64_json`, forwarded to providers that honor it |
| `user` | no | End-user identifier. Sent to the provider only on your own key: see [End-user identifiers](/v3/general/byok#end-user-identifiers) |
| `safety_identifier` | no | End-user identifier for OpenAI's safety checks, up to 128 characters. Sent to OpenAI only on your own OpenAI key: see [End-user identifiers](/v3/general/byok#end-user-identifiers) |
| `metadata` | no | Accepted. It is not a tag: to label calls for usage tracking, use `tags` |
| `extra_headers` | no | Additional HTTP headers forwarded to the provider. Credential headers (`Authorization`, `Proxy-Authorization`, `X-API-Key`, `API-Key`) are refused with `422` |
| `routing` | no | [Provider routing](/v3/llms/provider-routing) preferences. With a `provider/model`, only `zero_data_retention` applies |
| `tags` | no | Key/value labels recorded with the call, for [usage tracking](/v3/general/tags) |

Only the provider-specific image parameters `background`, `input_fidelity`, `moderation`, `output_compression`, `output_format`, `partial_images`, `quality`, `response_format`, `style`, `add_watermark`, `aspect_ratio`, `cfg_scale`, `enhance_prompt`, `guidance_scale`, `height`, `image_size`, `negative_prompt`, `num_inference_steps`, `output_mime_type`, `person_generation`, `prompt_upsampling`, `raw`, `resolution`, `safety_filter_level`, `safety_tolerance`, `seed`, `steps`, `style_preset`, `watermark`, and `width` are forwarded to the provider. `partial_images` is forwarded, but partial images arrive only on a streamed response, which these endpoints do not support. Any other top-level field not listed on this page is dropped before the provider is called.

Some fields are refused with `422` instead of dropped:

- A field that decides the provider connection, region, or how the call is made, priced, or answered, such as `api_key`, `api_base`, `base_url`, `timeout`, or `max_retries`.
- `stream` or `fallbacks`, unless the value is `false`, `null`, `0`, an empty string, or an empty list or object. The string `"false"` is refused. See [Limitations](#limitations).
- A server-side secret reference: a key or string value starting with `os.environ/` or `oidc/`, at any depth and in any field except `prompt`.

These rules apply to a JSON body. A `multipart/form-data` edit reads a fixed set of form fields and ignores the rest without an error (see [Editing images](#editing-images)).

### Saving the image to disk
{/* skip-test: continues the sample above, whose result it reads */}
<CodeGroup>
```python Python
import base64

# Assuming `result` is the response from POST /v3/images/generations above
image = result["data"][0]

if image["b64_json"]:
    with open("output.png", "wb") as f:
        f.write(base64.b64decode(image["b64_json"]))
else:
    # The provider returned a hosted URL instead of inline base64
    import requests
    with open("output.png", "wb") as f:
        f.write(requests.get(image["url"]).content)
```
</CodeGroup>

<Note>
Some providers return a hosted `url` instead of inline `b64_json`. Download the image if you want to keep it, since those URLs can expire.
</Note>

## Editing images

`POST /v3/images/edits` takes the same fields as generations plus an `images` array. Each entry sets exactly one of `file_id` (returned by Eden's `/v3/upload/...` endpoints) or `image_url` (an `https://` URL or a `data:image/...;base64,...` URL). An optional `mask` (same shape) marks the regions to edit.

The endpoint dispatches on `Content-Type`: send `application/json` for the `images[]` form below, or `multipart/form-data` for the classic OpenAI SDK file-upload form.

A multipart form reads only `model`, `prompt`, `image` (or `image[]`), `mask`, `size`, `n`, `user`, `safety_identifier`, and `routing` (as a JSON string). Every other form field is ignored without an error: provider parameters such as `quality`, `background`, or `output_format` are not forwarded, and `stream` and `fallbacks` are not refused, so the call answers with one JSON response from the one model it names. Use the JSON form to send any other field.
<CodeGroup>
```python Python
import requests

url = "https://api.edenai.run/v3/images/edits"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
}

payload = {
    "model": "vertex/gemini-2.5-flash-image",
    "prompt": "Make the background dark blue",
    "images": [
        {"image_url": "https://www.edenai.co/docs/images/hero-light.png"}
    ],
    "size": "1024x1024",
}

response = requests.post(url, headers=headers, json=payload)
result = response.json()
print(result["data"][0]["b64_json"][:60])
```
</CodeGroup>

<Info>
`image_url` with an `https://` URL works for providers that accept remote URLs (e.g. Gemini). For `openai/gpt-image-*`, pass a `data:` URL or upload the file via `/v3/upload/...` and reference it by `file_id` instead — those models do not accept remote URLs.
</Info>

## Listing image models

```bash cURL
curl https://api.edenai.run/v3/images/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Limitations

- **No streaming.** On a JSON body, `stream: true` is refused with `422`; `false`, `null`, and the other empty values listed under [Request parameters](#request-parameters) are dropped. A multipart edit ignores `stream` and answers with one JSON response.
- **No `fallbacks`.** On a JSON body, a `fallbacks` list with entries is refused with `422`; `[]` and `null` are dropped. A multipart edit ignores `fallbacks` and runs only the named model. Specify a single explicit `provider/model`.
- **`/v3/images/variations` is not implemented.**
