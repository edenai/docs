`@edenai` is not a model. It is a request for Eden AI to choose one for you, per request, from what the request actually contains.

```json
{
  "model": "@edenai",
  "messages": [{"role": "user", "content": "Explain machine learning"}]
}
```

The model is chosen before the request runs, so it goes through the same inventory, pricing and region checks as a model you name yourself. The response is an ordinary chat completion, and the model that answered is in its `model` field.

```python Python
import requests

url = "https://api.edenai.run/v3/chat/completions"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.post(url, headers=headers, json={
    "model": "@edenai",
    "messages": [{"role": "user", "content": "Explain machine learning"}]
})

print(response.json()['choices'][0]['message']['content'])
```

## Restricting the choice to a shortlist

Left alone, `@edenai` chooses among every model Eden AI can rank. `router_candidates` narrows that to a list you control.

```python Python
import requests

url = "https://api.edenai.run/v3/chat/completions"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.post(url, headers=headers, json={
    "model": "@edenai",
    "router_candidates": [
        "openai/gpt-5.5",
        "openai/gpt-5-nano",
        "anthropic/claude-haiku-4-5"
    ],
    "messages": [{"role": "user", "content": "Write a Python function to merge two sorted lists"}]
})

print(response.json()['choices'][0]['message']['content'])
```

Each entry is a concrete `provider/model` id, the kind listed under `endpoints` in [the model listing](/v3/llms/listing-models). Order matters: the first entry is also the one Eden AI uses if the models cannot be ranked, so list them in preference order. The list takes at most 64 entries of up to 128 characters each.

### Entries that cannot be ranked are skipped

The router ranks the models it has evaluated, and that is not every id Eden AI serves. An entry it cannot rank does not fail the request: it is dropped from the pool and reported back to you.

```json
"auto": {
  "selection": "ranked",
  "chosen": "openai/gpt-5-nano",
  "dropped": ["openai/gpt-5-search-api"],
  "quality_cost": null
}
```

The request fails with `422` only when nothing is left, and the error names every entry it dropped.

## Trading quality for cost

`routing.quality_cost` says how much answer quality you will trade for a cheaper model. It runs from 0 to 10.

| Value | Asks for |
|---|---|
| Unset | Quality first. **Default** |
| `0` | The best model for this request |
| `1` to `9` | A blend, weighted towards cost as the number rises |
| `10` | The cheapest model that can still handle the request |

```python Python
import requests

url = "https://api.edenai.run/v3/chat/completions"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}

response = requests.post(url, headers=headers, json={
    "model": "@edenai",
    "router_candidates": [
        "openai/gpt-5.5",
        "openai/gpt-5-nano",
        "anthropic/claude-haiku-4-5"
    ],
    "routing": {"quality_cost": 8},
    "messages": [{"role": "user", "content": "Reply with one word: hello"}]
})

print(response.json()['model'])
```

Leave it unset and Eden AI optimises for quality, which is why a one-line prompt can still reach a large model unless you ask otherwise.

<Info>
`quality_cost` is the only `routing` field that changes **which model** you get. [`routing.sort`](/v3/llms/provider-routing#choosing-an-objective) chooses between the providers of a model and never changes the model, so asking for a cheaper provider will not quietly downgrade your answer.
</Info>

## How it composes with provider routing

Two questions get answered on an `@edenai` request: which model, then which provider serves it.

When ranking succeeds, it names a provider along with the model, so the second question is already settled. When it cannot rank and Eden AI falls back to one of its default models, that model is a bare name, and [provider routing](/v3/llms/provider-routing) resolves it exactly as if you had sent it yourself: your `routing.sort`, `routing.allowed_providers`, sticky affinity, region and failover all still apply.

## What the ranking step looks at

Ranking models means describing your request. The ranking step works from a digest, never the full request.

**Looked at**

- System text, plus the last **8 turns** of the conversation, capped at **16,000 characters** in total. Older turns are dropped first.
- The **names and descriptions** of your function tools.
- Message content is hashed, not stored, once the ranking is done.

**Never looked at**

- Images, files and audio.
- Tool results, and the arguments of tool calls. A tool call contributes its name only.
- Reasoning items.
- Anything older than those last 8 turns.

If nothing textual survives, an image-only prompt for instance, ranking is skipped altogether and Eden AI applies a default. See [Data Retention](/v3/data-governance/data-retention) for what Eden AI itself keeps.

## Routing never fails your request

Ranking is a hint, not a requirement. If it is slow, fails, or answers with a model outside the pool, Eden AI applies a default and your request carries on:

1. Your first `router_candidates` entry that survived filtering.
2. Otherwise the first of Eden AI's default models with a provider callable on your endpoint and region.
3. Otherwise the first model left in the pool.

All three report themselves as `selection: "default"` in the [metadata](#seeing-what-was-chosen).

Some requests are never ranked at all. A pool of one model is its own answer, reported as `selection: "single"`. An empty digest takes a default, and so does a request arriving while ranking is briefly paused after repeated failures.

Waiting is bounded too. Ranking gets a few seconds and is not retried when it is merely slow, because a routing decision that costs more than it saves is not worth having.

### The errors you can still get

| Status | When |
|---|---|
| `422` | Every entry in your `router_candidates` was dropped, and the message names them. Also when the list breaks the 64 entry or 128 character bounds |
| `451` | On a [regional endpoint](/v3/data-governance/eu-endpoint), a candidate is not available in that region |
| `503` | There is nothing at all to route to |

## Seeing what was chosen

Send `x-edenai-metadata: enabled` and the response carries an `auto` block inside `edenai_metadata`, saying how the model was chosen. It is `null` on every request that named its own model.

```json
"edenai_metadata": {
  "requested": "@edenai",
  "strategy": "auto",
  "auto": {
    "selection": "ranked",
    "chosen": "openai/gpt-5-nano",
    "dropped": ["azure/gpt-5.5"],
    "quality_cost": 8
  }
}
```

| Field | Meaning |
|---|---|
| `selection` | How the model was arrived at. See below |
| `chosen` | The model handed to the pipeline. A `provider/model` id, or a bare model name when one of Eden AI's default models was applied |
| `dropped` | The `router_candidates` entries that could not be ranked |
| `quality_cost` | The value you sent, unchanged. `null` if you sent none |

| `selection` | Meaning |
|---|---|
| `ranked` | The candidates were ranked for this request and the best one chosen |
| `single` | One candidate was eligible, so there was nothing to rank |
| `default` | The candidates could not be ranked this time, so a default was applied: your first candidate, or Eden AI's own default when you named none |

The block reports the outcome, not the machinery: it does not say why a `default` was applied, because that is Eden AI's to watch rather than yours.

```python Python
import requests

url = "https://api.edenai.run/v3/chat/completions"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
    "x-edenai-metadata": "enabled"
}

response = requests.post(url, headers=headers, json={
    "model": "@edenai",
    "routing": {"quality_cost": 10},
    "messages": [{"role": "user", "content": "Reply with one word: hello"}]
})

print(response.json().get('edenai_metadata', {}).get('auto'))
```

See [Request Metadata](/v3/llms/request-metadata) for the rest of the block and how to read it off a stream.

## Where it works

`@edenai` is accepted on the three chat dialects, streaming and non-streaming: `/v3/chat/completions`, `/v3/responses` and `/v3/v1/messages`. It is not available on [embeddings](/v3/llms/embeddings) or on `/v3/universal-ai`, which both need a concrete `provider/model`.

It is a routing instruction, not a catalogue entry, so it never appears in `/v3/models`.
